## Ingester Command Reference

The LogTapestry Ingester is a hosted service that monitors log files and ingests them into a structured data store. It supports several command-line flags for operational control and validation.

### Syntax

```bash
LogTapestry.Ingester [options]
```


### Options
- `--validate`: Validates the configuration file and directory paths without starting the service. Exits with code 0 on success, 1 on failure.
- `--zap-db`: Deletes all contents of the data directory (including the state database) before starting. Use with caution.

### Configuration Overrides
The Ingester primarily uses `appsettings.json` for configuration. The following settings in `Ingester` section can be overridden via environment variables or command-line arguments when using Microsoft.Extensions.Configuration:

| Command-Line Flag | Configuration Key | Default Value | Description |
|-------------------|-------------------|---------------|-------------|
| N/A | `Directory` | (required) | Root directory to monitor for log files |
| N/A | `IncludePatterns` | `["**/*.log", "**/*.txt"]` | Glob patterns for files to include |
| N/A | `ExcludePatterns` | `[]` | Glob patterns for files to exclude |
| N/A | `DataRoot` | `"data"` | Directory for state database and working files |
| N/A | `LogLevel` | `"Information"` | Logging level: Verbose, Debug, Information, Warning, Error, Fatal |
| N/A | `PollingIntervalMs` | `1000` | Interval in milliseconds for polling changes |
| N/A | `FileReaderThreadPoolSize` | `Environment.ProcessorCount * 2` | Number of threads for reading and parsing files |
| N/A | `StateWriterBatchSize` | `1000` | Number of entries to batch when writing state |
| N/A | `StateWriterIntervalSeconds` | `2` | Interval in seconds between state writes |

### Operational Modes
- **Normal Mode**: Runs continuously, monitoring and ingesting logs.
- **Validation Mode**: Use `--validate` to check if the configured `Directory` exists and is accessible. Useful in deployment pipelines.
- **Clean Start Mode**: Use `--zap-db` to clear all persistent state before starting. Useful for testing or resetting the system.

### Examples

```bash
# Start the ingester normally
dotnet LogTapestry.Ingester.dll

# Validate configuration before deployment
dotnet LogTapestry.Ingester.dll --validate

# Start with clean state (deletes data directory contents)
dotnet LogTapestry.Ingester.dll --zap-db

# Combine validation and clean start
dotnet LogTapestry.Ingester.dll --validate --zap-db
```

## Compactor Command Reference

The LogTapestry Compactor merges small Parquet files in landing directories into larger, more efficient files based on age thresholds.

### Syntax

```bash
LogTapestry.Compactor --data <path> --compact-older-than <timespan>
```


### Options
- `--data`: (Required) Root directory of the Parquet data store.
- `--compact-older-than`: (Optional) Do not compact partitions newer than this timespan. Format: `1h`, `2d`, `30m`. Default: `1h`.

### Default Values
- `--compact-older-than`: Defaults to `1h` if not specified.

### Dry-Run Options
The Compactor does not have an explicit dry-run mode. However, you can simulate its behavior by:
1. Running with `--compact-older-than` set to a very short duration (e.g., `1m`) to see which partitions would be candidates.
2. Checking the console output for "Compaction candidate" messages without actually modifying data.

### Examples

```bash
# Compact all partitions older than 1 hour (default)
dotnet LogTapestry.Compactor.dll --data "C:\logs\parquet"

# Compact only partitions older than 24 hours
dotnet LogTapestry.Compactor.dll --data "C:\logs\parquet" --compact-older-than "24h"

# Compact partitions older than 30 minutes
dotnet LogTapestry.Compactor.dll --data "C:\logs\parquet" --compact-older-than "30m"
```


### Age Threshold Rules
A partition is eligible for compaction if:
1. Its last write time is older than the `--compact-older-than` threshold.
2. It contains a `landing/` subdirectory with Parquet files.
3. It does NOT contain a `_COMPACTION_COMPLETE` marker file.

After successful compaction:
- The `landing/` directory is deleted.
- A `_COMPACTION_COMPLETE` marker file is created to prevent reprocessing.

## Query Tool Command Reference

The LogTapestry Query tool executes SQL queries against the ingested log data and returns results in various formats.

### Syntax

```bash
LogTapestry.Query --database-path <path> --data-path <path> --output <format> <query>
```


### Arguments
- `query`: (Required) SQL query to execute. Use `{data_path}` as a placeholder for the data directory.

### Options
- `--database-path`: (Required) Path to the `state.sqlite` database file.
- `--data-path`: (Required) Path to the data directory containing Parquet files.
- `--output`: (Optional) Output format: `table`, `json`, `csv`. Default: `table`.

### Output Formatting
- `table`: Renders results in a formatted table using Spectre.Console.
- `json`: Outputs results as pretty-printed JSON array.
- `csv`: Outputs results as CSV with quoted fields.

### Connection Settings
The tool uses:
- **DuckDB**: In-memory database for querying Parquet files.
- **SQLite**: `SqliteStateProvider` for metadata and state information.

### Examples

```bash
# Query with table output (default)
dotnet LogTapestry.Query.dll --database-path "data/state.sqlite" --data-path "data" --output table "SELECT * FROM logs WHERE level = 'ERROR'"

# Query with JSON output
dotnet LogTapestry.Query.dll --database-path "data/state.sqlite" --data-path "data" --output json "SELECT timestamp, message FROM logs LIMIT 5"

# Query with CSV output
dotnet LogTapestry.Query.dll --database-path "data/state.sqlite" --data-path "data" --output csv "SELECT * FROM logs WHERE timestamp > '2023-01-01'"

# Using {data_path} placeholder in query
dotnet LogTapestry.Query.dll --database-path "data/state.sqlite" --data-path "data" --output table "SELECT COUNT(*) FROM parquet_scan('{data_path}/2023/01/01/compacted.0.parquet')"
```

## Error Messages and Exit Codes

### Ingester
- **Exit Code 0**: Success (normal exit or successful validation).
- **Exit Code 1**: Failure (validation failed or unhandled exception).
- **Error Messages**:
  - `Validation failed: Directory '{Directory}' does not exist.`: The configured `Directory` path does not exist.
  - `Validation failed: {Message}`: Other validation errors.
  - `[--zap-db] Error deleting data DB directory contents: {Message}`: Failed to clean the data directory.

### Compactor
- **Exit Code 0**: Success (normal exit).
- **Exit Code 1**: Not used; errors are logged but do not terminate with exit code 1.
- **Error Messages**:
  - `Compaction error for {partitionPath}: {ex}`: Exception during compaction of a partition.

### Query Tool
- **Exit Code 0**: Success (query executed, regardless of SQL errors).
- **Exit Code 1**: Not used; all errors are handled within the process.
- **Error Messages**:
  - `Unknown output format specified. Use 'table', 'json', or 'csv'.`: Invalid `--output` value.
  - `An error occurred after {stopwatch.ElapsedMilliseconds}ms:`: Followed by exception details.

### Common Error Handling
The application uses structured logging with Serilog. Errors are written to:
- Console output
- `logs/ingester-errors-.json` (rolling daily, JSON format)
- `logs/ingester-.log` (rolling daily, text format)

## Argument Parsing with System.CommandLine

### Overview
The LogTapestry suite uses `System.CommandLine` for argument parsing in the Compactor and Query tools. The Ingester uses a simpler `args.Contains()` approach for its two flags.

### Implementation Details

#### Compactor and Query Tools
Both use `System.CommandLine` with the following pattern:
1. Define `Option<T>` and `Argument<T>` objects with descriptions.
2. Create a `RootCommand` and add options/arguments.
3. Set an action delegate using `SetAction()` that receives a `ParseResult`.
4. Call `Parse(args).Invoke()` to execute.


```csharp
var dataOption = new Option<string>("--data") {
    Arity = ArgumentArity.ExactlyOne,
    Description = "Root directory of the Parquet data store"
};
var rootCommand = new RootCommand("LogTapestry Compactor Utility");
rootCommand.Add(dataOption);
rootCommand.SetAction(async parseResult => {
    var data = parseResult.GetValue(dataOption);
    // Execute logic
});
return rootCommand.Parse(args).Invoke();
```


#### Ingester
The Ingester uses manual argument checking:

```csharp
bool validate = args.Contains("--validate");
bool zapDb = args.Contains("--zap-db");
```

This approach is simpler but less feature-rich than `System.CommandLine`. It's sufficient for the Ingester's limited CLI interface.

### Cross-References to Configuration Files
- **Ingester**: Command-line flags map to settings in `appsettings.json` under the `Ingester` section.
- **Compactor**: All options must be provided via command line; no configuration file support.
- **Query**: All options must be provided via command line; no configuration file support.
