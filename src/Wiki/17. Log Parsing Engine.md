## Introduction
The Log Parsing Engine is a modular system designed to process unstructured log files into structured data for analysis and storage. It uses configurable regex patterns to extract fields from log entries and supports both single-line and multi-line log formats. The engine is built with performance, extensibility, and error resilience in mind, leveraging asynchronous streaming and efficient memory management.

## Core Components

### FileReader
The FileReader component reads log files in chunks and streams lines to the appropriate parser based on file type and configuration. It uses a factory pattern to instantiate the correct parser (regex, CSV, etc.) and manages file position tracking for incremental processing.

### ILogParser Interface
The ILogParser interface defines the contract for all log parsers:
```
csharp
public interface ILogParser : IAsyncDisposable
{
    Task<ParseChunkResult> ParseNextChunkAsync(Stream stream, CancellationToken token);
}

```
This interface enables extensibility through custom parser implementations and ensures consistent behavior across different parsing strategies.

### RegexLogParser
The RegexLogParser implements the ILogParser interface using configurable regular expressions with named capture groups to extract structured data from unstructured log lines. It supports timestamp, log level, and custom field extraction.

## Architecture Overview
The log parsing engine follows a streaming, chunk-based architecture that processes log files incrementally without loading entire files into memory. This design enables efficient processing of large log files and supports real-time ingestion.

### Multi-line Log Entry Handling
The engine handles multi-line log entries by using a start-of-entry regex pattern to identify the beginning of new log entries. When a line matches the StartOfEntryRegex, any in-progress entry is finalized and a new entry is started.

```
csharp
if (_startOfEntryRegex.IsMatch(line)) {
    if (_inProgressEntry != null) {
        yield return FinalizeEntry(_multiLineBuffer, _inProgressEntry, _entryParseFailed);
    }
    (_inProgressEntry, _entryParseFailed) = StartNewEntry(line);
    _multiLineBuffer.Clear();
    _multiLineBuffer.AppendLine(line);
} else {
    _multiLineBuffer.AppendLine(line);
}

```

This approach allows the parser to accumulate multiple lines into a single log entry, which is essential for handling stack traces and other multi-line log formats.

### Field Schema Inference
The RegexLogParser extracts custom fields using configured regular expressions with named capture groups. Field types can be specified as "long" or "double" for automatic type conversion:

```
csharp
foreach (var fieldRegex in _regexConfig.FieldsRegexes)
{
    var matches = Regex.Matches(finalMessage, fieldRegex.Regex);
    if (matches.Count > 0)
    {
        var match = matches[^1];
        var valueStr = match.Groups[1].Value;
        object value = valueStr;
        if (fieldRegex.Type == "long")
        {
            if (long.TryParse(valueStr, out var longValue))
            {
                value = longValue;
            }
        }
        else if (fieldRegex.Type == "double")
        {
            if (double.TryParse(valueStr, out var doubleValue))
            {
                value = doubleValue;
            }
        }
        fields[fieldRegex.FieldName] = value;
    }
}

```

## Performance Considerations
The log parsing engine includes several performance optimizations:

### Buffering and Memory Management
- Uses a 16KB default buffer size for efficient I/O
- Reuses StringBuilder instances to reduce allocations
- Processes lines in chunks (default 1000 lines per chunk)
- Uses compiled regular expressions for faster matching
- Implements buffer compaction to minimize memory allocations
- Utilizes Span<byte> for efficient memory operations


```csharp
protected const int DefaultBufferSize = 16384;
protected readonly StringBuilder WorkingStringBuilder = new StringBuilder(1024);
_startOfEntryRegex = new Regex(pattern, RegexOptions.Compiled);
```


### Regex Optimization
- All regex patterns are compiled with RegexOptions.Compiled
- Field extraction uses the last match (matches[^1]) to handle multiple occurrences
- Empty or invalid regex configurations are skipped

### Stream Processing
- Files are processed incrementally without loading into memory
- Stream position is used as the source of truth for checkpointing
- Asynchronous methods prevent blocking I/O operations
- Efficient byte-level line ending detection for \r, \n, and \r\n sequences

### Configuration-Based Limits
- MaxEntriesPerDataBlock limits data block size
- MaxRecordsPerChunk limits CSV parsing
- Configurable polling intervals reduce system load

## Troubleshooting Guide

### Parsing Error Handling
The engine handles parsing errors through the ParsingResult and ParsingFailure classes:


```csharp
public record ParsingResult(
    bool IsSuccess,
    LogEntry? Entry,
    string? ErrorMessage,
    string? UnparseableText,
    string Source
);

public record ParsingFailure(string ErrorMessage, string Source, string? ProblematicText = null);
```


When a parsing error occurs:
1. The error is logged using Serilog at Warning level
2. A ParsingFailure is added to the ParseChunkResult
3. Processing continues with the next line


```csharp
_logger?.LogWarning("Plugin: {name}, failed to parse timestamp for line: {Line}", Settings.Name, line);
```


### Common Issues and Solutions

**Malformed Lines**
- Issue: Lines that don't match expected patterns
- Solution: Ensure regex patterns are correctly configured and test with sample data

**Encoding Issues**
- Issue: Invalid UTF-8 sequences in log files
- Solution: The engine uses UTF-8 decoding with fallback handling

**Multi-line Entry Problems**
- Issue: Incomplete multi-line entries at chunk boundaries
- Solution: The parser maintains state between chunks and flushes buffered entries at appropriate times

**Performance Bottlenecks**
- Issue: Slow parsing of large files
- Solution: Optimize regex patterns, increase buffer sizes, or adjust chunk processing limits
